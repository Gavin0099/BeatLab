One app-owned ConfigurationStore on the main actor is configuration authority; Home/Metronome/Practice read the same instance. Views send edits; they do not own separate configuration copies.

Core: Tempo accepts integer BPM 30...240 (inclusive), rejects invalid init/decode; TimeSignature supports 2/4, 3/4, 4/4, 6/8; Subdivision explicitly distinguishes simple and compound meter; configuration rejects incompatible subdivision. Changing meter keeps compatible subdivision or selects its documented default in one transaction.
6/8 BPM unit is dotted quarter (two beats/bar); base subdivision is compound eighth (three pulses/beat), not six quarter beats.

Storage: one schema-versioned JSON envelope in UserDefaults, tempo/timeSignature/subdivision/accentEnabled. Missing/corrupt values show safe defaults. An unsupported schema is retained and edits blocked until explicit reset; no automatic data downgrade. A changed value is encoded/saved before publishing; encode failure leaves prior configuration. UserDefaults does not expose durable disk-write acknowledgement; relaunch is verified separately.

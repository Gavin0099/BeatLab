# BeatLab 練習遊戲設計

2026-10-04，GAME-DESIGN-01 無聲設計完成；後續 GAME-01 已將「節奏旅程」套入原生 App，BeatLab 0.1.0（4）已安裝並啟動於 owner iPhone；後續三種夥伴改版已於 0.1.0（5）更新安裝。

將現有十關跟拍練習做成短回合的「節奏旅程」。學習目標仍是把拍點打穩；遊戲感來自可見的進程、明確的手別與休止提示，以及完成後可立即再挑戰的回饋。暖白、紫色、大鼓墊延續目前識別。沒有加入生命值、排行榜、代幣或每日連續登入壓力。

## 兩個可操作方向

| 方向 | 選關方式 | 用途 |
|---|---|---|
| 節奏旅程（建議） | 依序排列的關卡節點、星星、下一個挑戰 | 起步時容易看懂自己走到哪裡 |
| 練鼓工作台 | 精簡課程清單、完成狀態、下一個挑戰 | 喜歡快速找課程與重練的使用者 |

兩者在設計稿共享準備、挑戰與結果。原生 App 採用「節奏旅程」；「練鼓工作台」仍為設計替代方向。年齡適用性仍是假設，需由 6–18 歲的實際使用者驗證；不以年齡直接強制選擇某個版型。

## 節奏內容

實際 ID、BPM、指示、手別/休止、細分數與四小節來自 `Sources/BeatLabCore/Resources/lessons.json`。顯示課名移除既有的兩位數前綴，另以「第幾關」呈現。

1. 大拍起步：找到大拍、左右輪流。
2. 分拍與留白：一拍兩下、八分左右手、留白也是節奏、八分與休止。
3. 節奏高手：一拍四格、十六分左右、反拍留白、節奏小高手。

R/L 是練習手別提示，單一螢幕鼓墊不辨識使用哪隻手。休止仍占節奏位置，UI 不把它移除。四分/八分依大拍分組；十六分每拍一列、四格由左到右。大字時重新排版，不能把不同拍的格子交錯成含糊的閱讀順序。

## 回饋與結果

固定的 R/L/— 表示譜型；即時填色加小圓點表示現在播放位置。停止後移除即時標記，譜型仍保留。節拍器的重音設定與此即時標記是不同狀態，不可共用一個外框語意。

原生提示只映射既有 `TimingGrade`：perfect →「剛剛好」、early/late →「早/晚了一點，下拍再跟上」、extra →「多打一下，下拍再跟上」。休止位置可給「這一格休息」教學提示，但不能重新決定 target matching 或 grade。未校正與不支援的音訊路由，不顯示毫秒精度。

星星沿用 `RhythmLesson.swift`：先滿足每關過關條件（命中 ≥85%、Perfect ≥55%、extra ≤10%）；零漏拍、零 extra 且 Perfect ≥95% 為三星；Perfect ≥80% 且 extra ≤5% 為二星；其餘已通過為一星。不得用連擊、動畫完成度或鼓墊點擊數重新計星。進度須保存成功才能解鎖，不能由結果頁動畫解鎖。

設計稿的通過範例使用約 93.75% 命中、87.5% Perfect、零 extra，依 targets 數取整，皆符合二星條件；再挑戰範例約 75%/37.5%、零 extra，不通過。這些是展示不同結果版型的 fixtures，並非使用者的實測成績。

## 可及性與動態

產品按鈕有效範圍至少 44 × 44 px；R/L/休止和鎖定原因都有文字。保留鍵盤原生焦點與 Enter 操作；回饋以 status 宣告，不逐動畫 frame 朗讀拍點。原生 VoiceOver 必須另外驗證，不應宣稱瀏覽器名稱檢查證明 SwiftUI VoiceOver 可用。

深色採現有 palette；大字重排節奏格、結果統計與底部導覽。Reduce Motion 停用鼓墊縮放，保留必要的穩定拍點顯示。實際鼓架距離下可讀性、可按性和兒童理解需 playtest。

## 設計稿邊界與落地順序

`beatlab-rhythm-quest.html` 為無聲互動設計稿。requestAnimationFrame 僅驅動視覺示範，沒有音訊或真正精度評分。點鼓墊的回饋依示範順序切換；結果不是由點擊推導。進度只保存在預覽本身的私有狀態，不寫入 App 的進度。可預覽通過、再挑戰、保存失敗、大字、深色與兩種選關方向；重新載入挑戰畫面時為靜態預覽，必須重新開始才播放示範。

原生落地先做課程入口和準備畫面，再接回既有時鐘、lane 與鼓墊，最後整合結果與保存復原。UI/導航屬 L1；任何 audio/UI/input 時鐘跨界或 scoring 變動升為 L2，另立精確檔案與失敗路徑契約。保留播放中設定變更與 6/8 語意；本設計十關皆為既有 4/4，不改節拍器 transport。

設計稿驗證在 `game-design-verification.json`，原始瀏覽器報告與七張截圖在 ignored `TestResults/GAME-DESIGN/`。HTML 仍為無聲示範，不用於原生結果或保存。

原生實作契約與證據在 `../slices/GAME-01.md`、`../slices/GAME-01-verification.json`：50 core、17 App、修正後 6 UI 流程通過，最大字級＋dark 重跑 3 個練習流程通過；候選 0.1.0（4）已原地安裝並啟動於 owner iPhone。原生挑戰接既有 elapsed／UIKit 鼓墊／matching，結果讀取真實 summary／stars；未加入 shipping fixture hooks。原生 timing、音畫同步、完整 VoiceOver／Reduce Motion、真機遊戲操作與兒童體驗仍待驗收；G1–G4 未因此接受。

## GAME-02：遊戲夥伴與冒險目的地

Owner 實際看到 build 4 後認為對兒童吸引力不足，接著指定參考字樹花園的貓咪、機器人與恐龍。課程節點與星星仍偏向清單，缺少孩子能記住的夥伴與值得走向的地方；原生練習因此加入可選夥伴，三篇章對應到起拍小島、回聲森林、星光舞台，搭配彎曲路線與島嶼節點。十關教學內容不變。

三個角色來自 owner 的 `english-vocab-trainer` 最新 main 中的正式透明 PNG。使用 CatRaisedPaw、RobotSkinMascot、DinosaurJunior，以及完成用的愛心／恐龍家族，共五張素材，保留原始 bytes。固定來源 commit、blob、SHA-256 與 BeatLab 資產對應見 `game-character-sources.json`。Garden checkout 未修改；該 App 的字彙提示／reward policy 不會因此移植到節奏評分。

孩子可在選關頁「換個夥伴」，選貓咪、機器人或恐龍；選擇只存在當次 App 的 View state，不寫入課程／設定 schema。所選角色接到場景、準備、鼓墊與結果，Home 的每日入口沿用同一選擇。三者的關卡、評分與星星規則相同，不鎖定角色。圖片本身是靜態 PNG；命中 Perfect 時給簡單放大／愛心或星光回饋，通關結果加星光與恐龍家族插畫。沒有骨架動畫、孵化、寵物成長、角色能力或額外判定。

回饋只讀取真實 grade／stars，Reduce Motion 停用角色縮放與結果出現動態。插畫不接收觸控，從 accessibility tree 移除；文字和原有 UIKit 鼓墊負責操作／回饋。原始鼓手咚咚插畫曾作為中途草稿接受 UI 檢查，但未安裝到手機；owner 指定素材後，最終選用上述三個夥伴。

三枚冒險徽章只從已保存的各篇章星星推導：前兩關、接著四關、最後四關皆通過才點亮對應徽章。沒有新資料欄位、代幣、連續登入或壓力獎勵；未通過與保存失敗不會解鎖。這是吸引力的設計假設，需由孩子真實練習後觀察理解、再玩意願與分心程度，不能從建置／UI 測試推導兒童喜歡。契約與本輪證據見 `../slices/GAME-02.md`、`../slices/GAME-02-verification.json`。

GAME-02 已加入貓咪／機器人／恐龍夥伴、三個冒險場景與篇章徽章；最新 BeatLab 0.1.0（5）已原地安裝於 owner iPhone 16 Pro。啟動被手機鎖定阻擋，待 owner 解鎖。一般 light 原有 3 個練習流程通過，選擇卡片修正後重驗旅程流程通過；最大字級＋dark 採組合證據：修正前不進入選擇器的每日流程通過，修正後夥伴旅程與零輸入結果共 2 個流程通過。不是單一最終 3 測試套件；保留中斷與失敗結果。 兒童吸引力仍需試玩；真機遊戲操作、物理 timing、成功徽章畫面、完整 VoiceOver／Reduce Motion、最小螢幕與 G1～G4 仍待驗收。

## GAME-03 被拒絕後：GAME-04 救援跑酷概念

Owner 明確指出角色跳島仍不算遊戲。GAME-03 的核心操作依然是鼓墊跟拍，移動與平台主要呈現成績；乾淨的畫面或角色動畫不能代替可玩的關卡。原生草稿保留、build 6 未安裝，也不把測試通過當作玩法接受。

重新提出「把恐龍蛋帶回家」：森林持續前進，石頭按節奏接近，按跳躍越過障礙並拿到能量星；漏跳／多按失去生命，三顆生命用盡可重試；收集至少八顆能量並抵達終點才救援成功。短關卡含四拍準備、單次與相鄰跳躍，讓玩家看得到目標、學會操作並面對有後果的挑戰。這些為提案，不是已接受的兒童教學或原生星星規則。

可玩的概念在 task-owned `artifacts/development/rhythm-rescue.html`。它使用現有恐龍素材、原創生成節拍與隔離的瀏覽器判定；不使用其他遊戲的圖／音樂／關卡，也不讀寫 App 進度。開始、暫停、失敗、重試、命中與通關需實際試玩，不能改成展示成功的腳本。原生版本仍要保留音訊／輸入 authority，另定 obstacle／生命／通關與保存的契約，再驗證真機及孩子的理解和再玩意願。

參考與重用規則保存在個人 skill `/Users/pc49-58/.codex/skills/beatlab-rhythm-game-design/SKILL.md`。參考文件核對日期為 2026-10-04；沿用 Nintendo 的 cue/action、ADOFAI 的可讀路徑、Duet Cats 的角色目的、Tiles Hop 的接近地形，不需每次重新搜同一組玩法。技能現已加入「先做完整短遊戲 loop，別把吉祥物動作當成遊戲」要求。

## GAME-06：配色與玩法回饋

Owner 拒絕 GAME-05：顏色不符合、畫面怪、玩起來不好玩。畫面同時用了手繪綠金棕森林、粗外框恐龍、奶白資訊和紫色按鈕；美術語言未統一是設計診斷，不能據此推定 owner 普遍不喜歡綠色。下一版先確認風格，再做角色、場景與 HUD 的完整小構圖，不先擴增素材。

既有概念只有十個固定跳躍時點、正弦波提示聲；每次漏跳或額外點擊扣一顆生命，三次結束；每次有效點擊給相同跳躍與一顆星。沒有完整音樂段落、漸進教學或可變化的回應組合。這些是機械事實，可能影響投入感，但不是獨立驗證的不好玩原因。

新提案是貓咪左右接魚：左右音符抵達、短音樂段落和角色回應，先做容易跟上的教學句，再引入左右交替、連打與休止；失誤讓下一句仍能練習。左右區域只辨識觸控位置，不辨識真實手別。這是待評估的替代方向，尚未製作或接受，不改 native input／評分／保存。

## 2026-10-05 — 原生跑酷與版面修正

Owner 在 build 6 真機圖再次拒絕遊戲感，指出節奏格被截斷；並明確選擇恐龍跑酷。GAME-07 移除包含整個場景的固定底部 inset，改為高度感知的單一遊玩 composition；不足高度／大字時整頁一起捲動。石頭位置只讀 audio elapsed 與既有 pattern ID，休止不放石頭；已配對的命中才清除障礙並跳躍，重複／extra 不增加清除。石頭越過角色只是呈現，晚到的合法命中仍由既有 matching 決定，沒有碰撞評分。

採原本恐龍圖搭配簡單扁平綠色場景／黄色跳躍鍵，保留節奏、進度與停止；完成／失敗、星星與保存沿用真實課程結果。此配色是試玩提案，未經 owner 接受；目前只有既有節拍聲，沒有歌曲配樂／跑步 sprite。手機安裝與真機試玩另記錄，不以模擬器通過宣稱好玩。
